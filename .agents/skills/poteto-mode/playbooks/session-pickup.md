### Session pickup

**Own the resume point. Read the prior trail rather than repeating it.**

1. Locate the prior Capy thread/task messages, PR, pushed branch and selected volume's
   run record. Read the overview and last messages, then the actual decision points.
   Use a read-only shared-machine task for a long authorized history and retain real
   thread/task references. Do not search unrelated projects or invent a transcript path.
2. Reconstruct the actual repository, branch, base/head, machine identity, task owners,
   open PRs, pending gates and decisions. The prior trail is evidence of intent; current
   native task state and actual commits decide what still exists after machine replacement.
3. Compare done versus pending, name the resume point and avoid redoing completed work.
   Reconcile an idle task before calling it done. Do not start a competing writer while
   an earlier owner is working/waiting. Missing unpushed files are missing, not recovered.
4. Route the remainder to its matching playbook: continue execution, ship an already
   evidenced recommendation, ratify or correct a conclusion, or postmortem a failed run.
5. Verify inherited claims against the original goal on the real artifact. Reuse sound
   evidence, but a prior self-report alone is not proof. Record stale or unavailable proof.

**Reply:** prior stopping point, inherited versus repeated work, recovered evidence,
missing state, current owners, the resume point and the observed outcome.
