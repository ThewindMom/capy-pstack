# Update to pstack 0.15.3

This revision ports pstack 0.15.3 through upstream commit
[`b42effe0`](https://github.com/cursor/plugins/commit/b42effe0aa50f59c693d7e2924714e015e00bf7c),
including [#414](https://github.com/cursor/plugins/pull/414) and the upgrade-help correction
in [#416](https://github.com/cursor/plugins/pull/416). Native distribution version is 1.2.0.
The imported source contains 158 files, with 34 changed since the previous source snapshot.
The reconstructed source was verified against GitHub's complete pstack subtree hash,
`f66b1f3ed67364a915305457ee9099edc44f9333`, before porting.

Every changed source file is accounted for in the
[update inventory](../../provenance/updates/0.15.3.json), including its old/new content hashes,
native destination and handling. The [current provenance](../../provenance/source.json)
records the complete source snapshot. These records do not fetch source at runtime.
The skills, playbooks and support files remain ordinary local files, with no submodule.

## New defaults and existing profiles

The upstream-faithful default panel now has **three** models: Opus 5.5 at `max`,
GPT-5.6 Sol at `max`, and Grok 4.7 at `xhigh` with fast priority requested. This applies to
arena, architect and interrogate. Arena still selects only one later cross-judge from
its pool. Concurrency controls waves, not total seats. Reflection remains three lenses
followed by synthesis, not another three-model panel.

Implementation, exploration and swarm roles request Grok 4.7. Judgment, prose,
explanation and reflection synthesis request Opus 5.5. Reflection tooling keeps Sol.
The source does not assign Comment Sicko a specific model, so that role still inherits.
The [local preset](../../.agents/pstack.model-presets.json) owns these assignments.

**Model identity is not account availability.** The public
[Capy model catalog](https://docs.capy.ai/models-and-pricing), checked on September 23, 2026,
did not list Opus 5.5 or Grok 4.7. Their preset names identify the required upstream models;
they are not claims that guessed Capy routes exist. Before dispatch, setup must observe the
actual native route, exact model version, supported reasoning settings and priority in the
account. The resolver requires a per-identity `bindings` entry with that observation's
reference. It emits the observed route unchanged. Merely listing a plausible ID in
`models` does not satisfy this requirement, and an older model cannot be relabelled as
the new version. See the [model policy](../../.agents/skills/poteto-mode/references/model-policy.md).

If the requested models are not available, the affected faithful role/panel is blocked.
A user-approved custom or single-model policy remains possible, but is not described as
faithful model parity. Neither installation nor tests create paid model runs.

Existing profiles are preserved. A pre-0.15.3 role or panel override can keep the old
defaults pinned, and rerunning setup must not silently rewrite a user's choice. Back up
the profile and inspect its roles/panels. Explicitly remove only the selected obsolete
overrides to use the new defaults, or retain them under an approved custom policy.
Preserve budget, concurrency and unrelated overrides. Version-1 profiles still need
explicit migration; no automatic migration is introduced.

## Verification starts before merge-ready

[Autopilot-full](../../.agents/skills/poteto-mode/playbooks/autopilot-full.md) starts an
independent verification round at the code-ready head and after each later patch-changing
push. Self-proof, CI and babysit proceed in parallel with those lanes. Each round includes
the real-surface and trunk-regression requirements plus at least two focused audit lanes.
The root audits merge-ready receipts before issuing a clean verdict on the patch to merge.

All proven defects go back to the owner together, including defects classified as notes.
Behavior findings require a red test covering every site with the same defect, or a
reproduction receipt where a test cannot show it. The next review brief carries that defect.
Owners keep the first merge base through fix rounds; a new rebase is reserved for merge
prep, a merge-tree conflict, or a trunk-caused CI failure. After merge prep, CI must pass
on the newly reported head before merging. Operator-held items still wait for the operator.

[Autopilot-stack](../../.agents/skills/poteto-mode/playbooks/autopilot-stack.md) uses the same
round model with STACK-READY instead of merge-ready, without granting merge authority.
The [multi-phase template](../../.agents/skills/poteto-mode/playbooks/multi-phase-plan.md)
now carries these rules. Its ten live lanes still resolve the `swarm workers` role locally,
so the plan checker does not embed a Cursor-only model slug.

## Limited lane-result reuse after a changed patch

[Shipping](../../.agents/skills/poteto-mode/playbooks/shipping.md) retains independent
per-PR review and bottom-up landing. If a patch differs only in tests, docs or lint config,
compare the outputs that each lane actually exercised: two builds at the verdict SHA and
one at the current head. Judge individual differences, not whole files. A difference is
noise only when it also occurs between the two old builds, or is an embedded commit SHA;
report every noise type and its files.

Only a lane whose differences are all explained noise may retain its result. Checks and
review of the changed patch still run fresh. A dev-server lane or other lane without build
output reruns. Other changed patches require re-verification. An unchanged patch-id keeps
the code verdict only with current-head mergeability and CI checks.

## Audits, stalls and measurement receipts

Owners record each child ID, expected runtime and state in `children.tsv`, retained with
the decision trail in the selected durable run volume. Native notifications and explicitly
authorized schedules drive audits, not detached VM sleepers. The audit program remains
responsible for every child after the final merge; a blocked Capy turn can end without
abandoning that program-wide reconciliation requirement.

A stuck task is marked and receives a targeted stop. The Capy port preserves its live-owner
safety rule: a replacement writer cannot gain an overlapping scope until the original
owner and publication authority are reconciled. A failed stop is a tracked blocked
replacement, never an excuse to lose the work. Read-only lanes can be replaced on separate
fresh machines while the obsolete result is retired. No stop or timeout means “passed.”
The root cannot grant or bypass approvals enforced by the forge.

[Swarm](../../.agents/skills/swarm/SKILL.md) now requires exact commit SHAs and, for
measurements, sample count, sample meaning and order in both the brief and result. A result
missing required receipts is discarded and gets one retry; a second miss is an explicit
gap, not a passing result. Workers report every proved issue. Audit status messages report
only new tracked changes; a quiet tick still gets a decision-log row.

## Append-only decision logs and smaller instruction updates

The [decision logger](../../.agents/skills/show-me-your-work/scripts/log.sh) now appends its
header rather than truncating the file when a network-mounted log incorrectly appears empty.
An actually empty file also receives a header. Existing TSV field/formula sanitization stays.
Regression tests inject the false-empty result and check that previous evidence survives.

The update also includes upstream's smaller wording and checklist changes in blast-radius,
figure-it-out, how's explorer prompt, bug fixes, feature design, principles, TDD, technical
writing, unslop and show-me-your-work. The native pause workflow already supports an honest
broken-state checkpoint; the removed upstream prohibition does not need to be reintroduced.
Full-autonomy defaults retain explicit operator gates and Capy permissions.

## Verification boundary

Run from the repository root:

```bash
python3 tools/catalog.py --check
python3 -m unittest discover -s tests -v
```

The [0.15.3 tests](../../tests/test_update_0153.py) exercise actual logger appends and resolver
outputs, old-pin preservation, observed-route bindings, identity checks and the update
inventory. Workflow text tests check that specified instructions remain in the files;
they are not evidence that a live agent followed them. Existing tests cover real terminal
behavior, offline project/volume installation and, with `PSTACK_BROWSER_TESTS=1` in CI,
Chromium behavior. CI also runs the bundled Bun tests and strict typecheck.

Actual model dispatch, verification-round events, merge-prep CI, build-output reuse,
child-stop reconciliation and audit wakeups still require the
[live checklist](../live-smoke.md) in an authenticated Capy workspace. No such live run was
performed by this source update. Do not treat fixtures as model-availability observations.
