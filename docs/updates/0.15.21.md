# Update to pstack 0.15.21

Native distribution 1.4.0 follows Cursor plugins revision
[`997ffc7f`](https://github.com/cursor/plugins/commit/997ffc7fe26bdaa6478a14e7f5b8d5f9ed747102).
The 167-file source snapshot reconstructs Git subtree
`8824c764d99583f7cc8059c915296e444c53f060`. The
[source inventory](../../provenance/source.json) maps every source file to a native
destination. The [update record](../../provenance/updates/0.15.21.json) preserves the
0.15.15 inventory and accounts for all 62 changed paths.

## Native behavior

`/ketchup` catches the user up from thread history without changing code or starting jobs.
It distinguishes decisions that need the user from work the agent can still do. The
receiving chat owns poteto-mode's playbook and delegation rather than spawning a second
coordinator to run the same playbook.

Workflow, review, investigation, and principle wording follows the new source where it
changes decisions or reduces repetition. Native task placement, model resolution, and
authorization remain explicit. Source defaults do not reset Personal Drive overrides.
The model preset still records 0.15.15, the revision at which its unchanged model choices
were adopted.

The executable updates cover plan validation, PR status handling, and worktree auditing.
Portable helpers remain optional. Capy's native callbacks remain the coordinator's
continuation mechanism; a local watcher does not own the PR lifecycle.

The new source `plugin.json` maps to the native `pstack.json` distribution metadata.
Cursor activation metadata is not installed. No runtime dependency on Cursor is added.

## Maintenance from the installed bundle

The bundle includes its accepted source inventory and a read-only upstream audit helper.
This avoids treating an older remote capy-pstack branch as the current installation.
Content drift is reported even without a version bump. The
[maintenance reference](../../.agents/skills/poteto-mode/references/upstream-maintenance.md)
requires a reviewed disposition for every path before advancing the baseline.

Maintenance stages work outside Drive, preserves managed-file customizations and unrelated
skills, and runs the safe installer's ownership preflight. It does not authorize commits,
PRs, merges, deployment, schedules, or model-policy changes by itself.
The source catalog rejects noncanonical file modes instead of passing a file that the
installer will later reject. Data files use `644`; executable helpers use `755`.

## Verification boundary

The release's Python tests assert the new explicit versions, counts, inventories, and
offline installation behavior. Historical 0.15.15 assertions use the preserved source
snapshot instead of requiring the latest source to remain at that release. Existing
behavioral assertions remain in place. Bun tests cover the changed portable tooling.

Static checks and helper tests do not prove all workflow triggering or native integration.
Three fresh native tasks evaluated Ketchup with synthetic positive, non-trigger, and
unavailable-history cases. Their responses kept superseding user directives, routed
cross-project recall away from Ketchup, and refused to invent missing statuses. Those
fixtures do not certify real PR state retrieval or discovery in every session.
Cross-machine handoffs, account entitlements, and PR callbacks still need their separate
[live smoke checks](../live-smoke.md). A scheduled check is live only when its actual
automation is enabled; installation alone creates no schedule.
